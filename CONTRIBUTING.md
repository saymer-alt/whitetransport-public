# Contributing / Правила изменений в форках и проектах saymer-alt

Этот документ описывает правила внесения изменений **в репозиторий saymer-alt**. Он не заменяет лицензию, требования исходного upstream, проектную документацию, политику веток и правила безопасности.

## Стандарт небольших и проверяемых изменений

Действует [единый инженерный стандарт](https://github.com/saymer-alt/saymer-infrastructure/blob/main/docs/engineering-change-review-standard.md) для разработчиков, сопровождающих и ИИ-агентов.

**Одна проблема → минимальное смысловое исправление → необходимые тесты → один обозримый PR → подтверждение результата.**

1. Сначала укажите воспроизводимый симптом и корневую причину (либо честно отметьте гипотезу).
2. Один PR должен решать одну независимую задачу. Не совмещайте hotfix с рефакторингом, косметическими правками и новыми функциями; отдельная проблема — отдельная Issue/PR.
3. Ограничивайте **смысловую область**, а не количество строк. Нужные для фикса тесты, документацию, проверку обратной совместимости и план отката оставляйте вместе с ним.
4. В PR указывайте затронутые файлы, исключённые работы, результаты тестов и непроверенное (`NOT_TESTED`). Зелёный CI или exit code 0 не заменяет проверку реального результата.
5. Большой неделимый diff допустим только с объяснением причин и явным решением ревьюера/владельца. Не делайте архитектурный rewrite под видом мелкого исправления.
6. Не изменяйте production, секреты, релизы и защищённые ветки без отдельных разрешений и обязательных проверок. Для docs-only допустим небольшой отдельный commit, если разрешено правилами репозитория.

**Авторство (человек или LLM) не отменяет ответственность за понятность, тестируемость и корректность изменения.**

## Минимальная форма PR

**Проблема / Issue** · **Причина** · **Объём и исключения** · **Проверки (PASS/FAIL/NOT_TESTED)** · **Риски / откат / оставшаяся работа**.
